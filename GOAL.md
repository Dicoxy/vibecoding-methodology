# GOAL — Методология блочного кодинга

**Версия 2 — черновик. Утверждён устно 8 сентября 2026, правит Гриша.**

**Цель:** методология, по которой один архитектор без программистского бэкграунда доводит систему от идеи до эксплуатации, где все роли кроме архитектора — механизмы; и по которой это может повторить другой человек со своей идеей и своей ставкой.

Два полюса в напряжении: «в одиночку» и «тем, кто вокруг». Это правильно — второй проверяет, что первый не сделан под одного человека.

---

## Полюс А — «в одиночку»

### A1. Один архитектор, остальные роли — механизмы
- **Статус:** достигнут (MARS: все архитектурные решения — один человек; реализация, память, диспетчеризация — механизмы).
- Фиксируется как достигнутый, чтобы не путать с целью.

### A2. Независимая приёмка
- **Цель:** ни один блок production-проекта не принимается тем, кто его сделал.
- **Как проверить:** `judge.sh` (судья результата, скрипт) и Architecture Judge (модель другой семьи) прошли мутационный тест — 5/5 дефектов пойманы, чистый контракт не отвергнут — и стоят в цикле MARS.

### A3. Портфель без потери
- **Цель:** архитектор ведёт ≥5 проектов в разных режимах внимания; ни один активный не стоит незакрытым >2 дней, спящий — стоит честно с условием пробуждения.
- **Как проверить:** LEDGER 30 дней подряд без ложных долгов и без пропущенных.

### A4. Метод не остаётся в проекте
- **Цель:** находки денежных проектов переносятся в методологию с forcing function, а не только текстом.
- **Как проверить:** за квартал ≥3 переноса «→ методология» из ≥2 разных проектов, у каждого — механизм принуждения (скрипт, шаблон, gate), не только раздел.

---

## Полюс Б — «тем, кто вокруг» — PARKED

**Условие пробуждения:** приёмка полюса А — A2 и A3 выполнены. До этого мы сами не знаем, что отдавать: методология с самоприёмкой и без леджера — передача собственных дыр.

### Б1. Свой проект до рабочего блока без Гриши
- **Цель:** человек без программистского бэкграунда, со своей идеей и своей ставкой, доводит свой проект до первого рабочего блока в проде по шаблонам методологии. Оркестратор — Claude по PROJECT-INSTRUCTIONS.
- **Как проверить:** один такой проект; замер — часы от идеи до блока, число обращений к Грише по существу (цель — ноль).

### Б2. Его память работает с нашими механизмами
- **Цель:** этот человек закрывает дни и ведёт CHANGELOG так, что LEDGER и RAG работают без настройки под него.

## Не-цели

- Не автоматизируем полностью: архитектор всегда в цикле — там, где у него своя ответственность.
- Не строим второго архитектора из сотрудника: архитектор — это своё «зачем», не навык (решение 06.09.2026).
- Не привязываемся к инструментам (Claude, Cline, Cursor — заменяемы).
- Не пишем академическую работу.
- Не документируем практику без forcing function: раздел без механизма не считается сделанным.
- **Форма продукта не решается до приёмки полюса А.** Сейчас — документ + процесс. Может оказаться программой. Решение отложено с условием, не запрещено.

# GOAL — Методология блочного кодинга

**Цель:** Создать повторяемый, документированный процесс разработки ПО с AI, который позволяет маленькой команде (2-3 человека) выпускать продукты на уровне, обычно требующем 10-20 человек и 6-12 месяцев.

---

## Измеримые критерии

### Критерий 1: Скорость запуска нового проекта
- **Сейчас:** каждый проект запускается вручную, настройка окружения и контекста занимает дни
- **Цель:** новый проект стартует за 2-4 часа (GOAL → BLOCKS → contracts → первый блок в работе)
- **Как проверить:** запустить Tier 2 проект по методологии, замерить время от идеи до первого рабочего блока

### Критерий 2: Передаваемость
- **Сейчас:** только Гриша может запустить и вести проект
- **Цель:** человек с техническим бэкграундом может вести проект по методологии после 1-2 часов онбординга
- **Как проверить:** дать Маше или новому человеку запустить проект по шаблонам

### Критерий 3: Сохранение контекста
- **Сейчас:** контекст теряется между сессиями, AI не знает что было решено
- **Цель:** любая AI-сессия получает полный контекст проекта за <10K токенов через RAG
- **Как проверить:** начать сессию с чистого контекста, задать вопрос про прошлое решение — RAG находит ответ

### Критерий 4: Качество на выходе
- **Сейчас:** MARS за 5 недель (2 человека) — доказательство работоспособности
- **Цель:** повторить результат на 2-3 разных проектах (CRM, KIBA, sovr-resheniya)
- **Как проверить:** каждый проект укладывается в оценку ±30%
